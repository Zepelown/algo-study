# Study Rules

## 기본 원칙

- 각자 원하는 문제를 선택해서 풉니다.
- 풀이 코드는 `members/{name}/{platform}/` 아래에 추가합니다.
- PR 하나에는 가능하면 문제 하나만 포함합니다.
- 정답 코드뿐 아니라 풀이 과정과 복잡도를 PR에 남깁니다.
- 외부 풀이, 블로그, AI 도구를 참고했다면 PR에 명시합니다.

## 디렉터리 규칙

```text
members/{name}/{platform}/{problem-id}.{ext}
```

- `{name}`: 스터디원 이름 또는 GitHub ID
- `{platform}`: `boj`, `programmers`, `leetcode` 등
- `{problem-id}`: 플랫폼의 문제 번호 또는 식별자
- `{ext}`: 사용한 언어의 확장자

## PR 규칙

- PR 제목은 `[플랫폼 문제번호] 문제 이름 - 이름` 형식을 사용합니다.
- PR 설명에는 풀이 요약, 접근 방식, 시간 복잡도, 공간 복잡도, 걸린 시간을 작성합니다.
- 리뷰어가 이해할 수 있도록 핵심 아이디어와 헷갈렸던 부분을 남깁니다.
- 리뷰 후 필요한 수정이 있으면 같은 PR에 반영합니다.

## 리뷰 기준

- 풀이 아이디어가 문제 조건에 맞는지 확인합니다.
- 시간 복잡도와 공간 복잡도가 입력 제한에 적절한지 확인합니다.
- 더 단순하거나 읽기 쉬운 접근이 있는지 제안합니다.
- 코드 스타일보다 풀이의 명확성과 정확성을 우선합니다.

## 커밋 예시

```text
solve: add boj 1000 solution for yoon
docs: add study rules
```
